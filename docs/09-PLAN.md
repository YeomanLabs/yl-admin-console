## M12 — On-prem Active Directory (Phase 2)

Design in `docs/11-ONPREM-AD.md`. Connects by LDAP straight to a domain controller as the signed-in Windows user —
the admin's own Kerberos ticket, so AD enforces what they have been delegated. No agent, no service account, keeping
CLAUDE.md non-negotiable 4 intact on-prem as well as in the cloud.

Most of the user half is not new UI: it is unlocking `DirectoryUser.OnPremMasteredProperties`, the 20 attributes
Phase 1 greys with "Mastered in on-prem AD (Phase 2)". Genuinely new are OUs, computer objects, and group scope and
category, none of which have a cloud equivalent.

Tested against a disposable DC (`D:\Lab`, `adlab.test`), because a fake covers the logic and cannot cover LDAP
semantics — and LDAP semantics are where the bugs are, exactly as the real Graph bugs only ever showed up live.

- [x] 12.1 🧪 `IDirectoryService`, the on-prem projections, LDAP error translation, and an in-memory fake. No LDAP and no package yet, so it stays testable anywhere. — done, 46 tests. Objects are addressed by `objectGUID` and never by distinguished name, because a DN changes the moment somebody renames or moves the object and acting on a stale one either fails or succeeds against whatever is at that path now. Three helpers exist because each is a known trap: `DistinguishedNames` (splitting on commas breaks `CN=Smith\, John`), `AccountFlags` (assigning `userAccountControl` instead of masking silently clears "password never expires" and "smartcard required"), and `DirectoryErrorText` (the useful detail is the Win32 sub-code AD buries in the diagnostic — `data 52e` — not the LDAP result code). The fake refuses what a real DC refuses — duplicate names in a container, deleting a non-empty or protected container, removing a primary group, a group containing itself — because a fake that says yes to everything teaches the calling code to assume yes. The namespace is `OnPrem`, not `Directory`: the latter shadowed `System.IO.Directory` across the whole of Core.
- [x] 12.2 🧪 `LdapDirectoryService`: DC discovery by SRV, Negotiate bind, connection lifetime, read a user by objectGUID. — written, not yet proven against a DC. `System.DirectoryServices.Protocols` added. Serverless binding — the LDAP client is handed the *domain*, not a hostname, so Windows finds a controller through DNS SRV and site topology rather than depending on one machine that will eventually be retired. The bind is Negotiate with signing and sealing, which authenticates as the admin (so AD enforces their delegation, matching non-negotiable 4) and also satisfies the encrypted-connection requirement for `unicodePwd` on port 389 — the difference between password resets working immediately and needing a certificate conversation first. `LdapAttributes` handles the encodings that are quietly wrong when done naively: AD timestamps have two different "never" sentinels, `objectGUID` must be escaped byte-by-byte to be searched for, a password is UTF-16 with literal quotes as part of the encoding, and `groupType` is a bit field carrying both scope and category. Filter values are escaped, so the search box is not an injection point. Clearing an attribute deletes it rather than writing "" — the same trap Graph sprang with `department`. **Now proven against a real domain controller** — and it found two bugs the fake never could. **One:** with explicit credentials the bind used `AuthType.Basic`, which a DC refuses outright over an unprotected connection and which would send the password in the clear even where accepted. Explicit credentials are an identity to bind *as*, not a different mechanism, so it is Negotiate either way; and signing and sealing now apply regardless, since the protection belongs to the connection rather than to whose identity is on it. **Two:** serverless binding is right in production and impossible from a machine that cannot resolve the domain, so `LdapOptions.Server` names a controller directly — also what you want when troubleshooting one DC in particular. Verified live against `adlab.test`: bind, the objectGUID round trip, the `immutableId` hybrid join, AD timestamps, `userAccountControl`, `groupType` decoded to scope and category for all four combinations, nested group members staying groups rather than being flattened, the OU tree, and a subtree search scoped to one OU.
- [x] 12.3 🖥 Read paths — users, groups, computers, the OU tree — and a Domain page showing what was found. — done. `OuNode` derives the tree from distinguished names, since AD stores no parent link; an OU whose parent was not returned attaches to the nearest ancestor that was, because dropping it would silently under-report the directory. `DomainPageViewModel` puts users, groups and computers in one row shape so switching between them does not move everything on screen, shows a group's scope and category without opening it, and treats "no domain controller reachable" as a stated reason rather than an empty list. Clicking an OU narrows the search to it, which needed a search base threading through the contract, the fake and the LDAP layer. (Finished in 12.4: the page was written but never registered in DI or put on the nav rail, so none of it was reachable — a reminder that “the ViewModel is done” and “the feature exists” are different claims.)
